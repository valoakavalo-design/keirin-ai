# 競輪予想AI（外部公開用スタンドアロン版）

レースを指定すると、出走表・並び予想・選手コメントを楽天Kドリームスから自動取得し、モデルv2で予想するWebアプリです。Muse ホスト版「競輪予想AI」の全機能を、外部サーバーへデプロイできる単体パッケージとして再実装したものです。

## 機能

- 日付 → 開催場 → レース番号の順に選ぶだけで自動予想（出走表・並び予想・コメント取得）
- モデルv2: 1着スコア／3着内スコアを分離したロジスティック回帰（2024年前半で学習、2024年後半13,903レースで検証: ◎1着率45.6%）
  - ◎ = 1着スコア首位、○▲△ = 3着内スコア順。ライン3番手以降は1着スコアで大きく減点（−0.49）
  - 予想勝率は1着スコアの softmax
- 勝負レースモード: ◎予想勝率55%以上で「勝負レース」。買い目は3連単フォーメーション（1着◎ → 2着○▲ → 3着○▲△ = 4点）
  - 検証（フォーメーション版）: 2024年5〜8月 回収率105.1%／9〜12月 120.0%（月によるばらつきあり、保証ではありません）
  - 55%未満は「見送り推奨」で、従来の3連単8点を参考表示
- オッズ収集と想定回収率: レース前の3連単オッズ（全通り）を自動収集し、買い目ごとにオッズ・モデル確率（Harville式の近似と明記）・想定回収率（EV = 確率×オッズ）を表示。買い目はEV順
  - オッズ 9999.9（発売実績なし等の上限表示）はEV計算から除外します
- 穴狙い: EV120%以上で「伏兵」（3着内スコア上位なのに印が薄い選手）を含む組み合わせを、根拠文つきで最大4点。当たりやすさではなく割安さの提示です
- 風: Open-Meteo（APIキー不要）で開催場座標×発走時刻の風向・風速・突風を取得し、ホーム直線／バック直線の風を表示（推定・出典明記）
  - 風は表示と展開解説のみに使い、スコアには入れません（2024年27,715レースの検証で風速帯別のライン先頭1着率は18.5%/17.4%/17.7%/18.6%とほぼ差がなかったため）
  - 開催場の座標・ホーム直線方位は `venues.json` の概略値です
- 出走表テーブル（白基調）: 得点・S・B・決まり手・率のセルをタップすると内訳モーダル
  - Sの車番別内訳は取得元にデータが無いため、捏造せず「取得不可」と明記し、S総数・出走数・S率とメンバー比較で代替しています
- 展開解説: 外部AIは使わず、ライン・スコア・風からテンプレート生成します
- 履歴・成績: 予想は自動保存。結果（着順・払戻）はユーザーが手入力し、全体／勝負レースのみの的中率・回収率を集計

## ブラインド設計（重要）

予想フローでは**結果・払戻ページを絶対に開きません**。取得するのは出走表・並び予想・コメントと、レース前情報であるオッズのみです。結果はユーザーが手入力します。

## 動作環境と起動

- Node.js 18以上（開発・検証は Node 24）。依存パッケージは**なし**（標準ライブラリのみ）なので `npm install` は不要です。

```bash
npm start
# → http://localhost:3000 （PORT 環境変数で変更可）
```

環境変数:

| 変数 | 既定値 | 説明 |
|---|---|---|
| `PORT` | `3000` | 待受ポート |
| `DATA_DIR` | `./data` | 予想履歴 JSON の保存先 |

初回起動時、`seed/predictions-export.json`（Muse ホスト版から書き出した履歴30件）を読み込んで `DATA_DIR/predictions.json` を作成します。

## デプロイ手順

### Render

1. このフォルダを GitHub 等のリポジトリに push する
2. Render で **New → Web Service** を作り、リポジトリを接続
3. 設定:
   - Runtime: Node
   - Build Command: （空欄で OK。依存なし）
   - Start Command: `npm start`
   - 環境変数 `PORT` は Render が自動で渡します（アプリは `process.env.PORT` を読むので追加設定不要）
4. 履歴を永続化する場合: **Disks** で永続ディスクを追加し、マウントパスに合わせて環境変数 `DATA_DIR`（例: `/var/data`）を設定する
   - ⚠️ 無料プランはディスクが使えず、ファイルシステムは再デプロイ・再起動で消えます（履歴も消えます）。本番運用は有料プランの永続ディスクか、外部DBへの移行を推奨

### Railway

1. **New Project → Deploy from GitHub repo** でリポジトリを接続（`npm start` が自動で使われます）
2. 環境変数 `PORT` は Railway が自動で渡します
3. 履歴を永続化する場合: **Volume** をサービスに追加し、マウントパス（例: `/data`）に合わせて `DATA_DIR=/data` を設定する
   - ⚠️ Volume が無いと履歴は再デプロイで消えます

### その他のホスト

`node server.js` が実行でき、`PORT` が渡る環境ならどこでも動きます（VPS、Fly.io、Cloud Run 等）。公開時は必要に応じてリバースプロキシやアクセス制限を前段に置いてください（本アプリ自体に認証はありません）。

## 構成

```
server.js            HTTP サーバー / API / 履歴ストア / 集計
lib/kdreams.js       Kドリームス取得・解析（出走表/並び/コメント/オッズ）
lib/model.js         モデルv2 スコア・買い目・穴狙い・展開解説テンプレート
lib/wind.js          Open-Meteo 風取得と直線別分類
model.json           学習済み係数（2024年前半で再フィット、検証値再現済み）
venues.json          開催場の座標・ホーム直線方位（概略値）
public/index.html    フロントエンド（単一ファイル、白基調）
seed/                初期履歴データ（30件）
data/                実行時に生成される履歴保存先（DATA_DIR で変更可）
```

## 注意

- 出走表・オッズの取得元（楽天Kドリームス）のページ構成が変わると、解析が壊れる可能性があります。
- オッズは予想時点のもので、締切までに変動します。想定回収率は近似確率に基づく目安です。
- 過去データの検証結果は将来の成績を保証しません。
